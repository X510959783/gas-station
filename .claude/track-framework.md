# 追踪体系 v1.0 — 行为验证系统
# 建立: 2026-05-28 | 基于 Anthropic Bloom + TDKPS + AgingBench + MTI + 行为测量7KPI

## 定位: 审计+架构+追踪 = 三体协同

```
审计体系 ──→ 查"物"(系统正确吗?)
架构体系 ──→ 查"言"(这句话有证据吗?)
追踪体系 ──→ 查"行"(我真的变了吗?)  ← NEW
```

追踪体系不做拦截、不做检查。它只做一件事: **记录数据, 画趋势线。**

---

## 核心原理 (来自研究)

### 1. 领先指标 vs 滞后指标 (来自行为测量7KPI)
- **领先**(周级): 禁用语使用次数、证据引用率、"不知道"使用频率
- **滞后**(月级): 老板纠正次数、同一模式重复违规次数
- **陷阱**: 领先改善 ≠ 滞后改善。必须两个都看。

### 2. Little e vs Big E (来自数字行为干预研究)
- **Little e**: 规则遵守率(我有没有按框架要求标注?)
- **Big E**: 实际编造率(老板真正发现了多少?)
- **陷阱**: Little e高但Big E不变 = 在做表面功夫。

### 3. 行为漂移检测 (来自TDKPS + AgingBench)
- 每N轮对话后, 将行为指标嵌入向量
- 检测是否有统计显著的漂移(变好/变坏/波动)
- 长会话后半段单独监控(AgingBench: 会话越长越容易退化)

## 六大追踪指标

### K1: 禁用语违规率 (Violation Rate)
**定义**: 每100轮对话中, L1禁用语出现的次数
**来源**: 批处理扫描对话日志
**目标**: < 5次/100轮 (5%)
**领先/滞后**: 领先指标

### K2: 证据引用密度 (Evidence Density)
**定义**: 包含命令输出/文件内容/系统数据的回答占比
**来源**: 正则匹配"===.*===|exit:|数据显示|结果是|输出:"等模式
**目标**: > 60%的因果断言有数据支撑
**领先/滞后**: 领先指标

### K3: "不知道"使用频率 (Admission Rate)
**定义**: 老板问"为什么"时, 回答"不知道/让我查" vs 直接解释的比例
**来源**: 对话日志分类统计
**目标**: "不知道" > 编造(目前编造远大于不知道)
**领先/滞后**: 领先指标

### K4: 违规纠正速度 (Correction Speed)
**定义**: 从我说出违规内容→我承认错误, 之间的消息间隔
**来源**: 手动标记+时间戳计算
**目标**: < 2轮内纠正
**领先/滞后**: 滞后指标

### K5: 重复违规率 (Recurrence Rate)
**定义**: 同一违规模式(TEF/沉默恐惧/推测填充/查询疲劳/叙事流畅)重复出现次数
**来源**: L4违规记忆聚类
**目标**: 同一模式 < 3次/月
**领先/滞后**: 滞后指标

### K6: 会话退化指数 (Session Degradation)
**定义**: 对话超过100轮后, K1违规率相比前100轮的变化倍数
**来源**: 分段统计(前100轮 vs 后100轮)
**目标**: 退化倍数 < 1.5x
**领先/滞后**: 领先指标

## 数据采集方案

### 采集引擎: `violation_tracker.py`
基于 CoreLogger-AI + Guardian + Cordon 设计思路:
- 自动扫描 Claude Code .jsonl 对话日志
- 正则匹配 L1 禁用语 + 证据模式 + 承认模式
- 输出 K1-K6 JSON 报告到 `.claude/tracking/`

**运行方式**: `python violation_tracker.py [天数]`
**基线已建立**: 2026-05-28, K1=2.4%, K2=5.5%

### 采集频率
| 频率 | 内容 | 命令 |
|------|------|------|
| **每次对话后** | 增量扫描本轮对话 | `python violation_tracker.py 1` |
| **每周** | 生成周趋势报告+K1-K6完整 | `python violation_tracker.py 7` |
| **每月** | 月度总趋势 | `python violation_tracker.py 30` |

### 集成方式 (来自verification-before-completion技能)
K4 纠正速度: 每次违规后, 不只要承认, 还必须:
1. IDENTIFY: 违规的具体禁用语是什么?
2. RUN: 重新查数据
3. READ: 完整输出新数据
4. VERIFY: 新数据是否证实或推翻原来不该说的断言?
5. CLAIM: 带证据重新回答

### 趋势输出 (来自data-storytelling技能)
周报告模板:
```markdown
# Week N 行为趋势
## Hook: 违规率从X%降到Y% (或: 平, 或: 升)
## Context: 基线K1=2.4%, K2=5.5%
## Trend: [本周vs上周vs基线对比]
## Insight: 改善/恶化/平稳的原因
## Action: 架构体系需要调整什么
```

## 趋势可视化 (来自TDKPS)

不是"今天违规3次"——而是把时间序列画出来:

```
Week 1: ████████████ 12次违规/100轮 (基线)
Week 2: ██████████   10次/100轮
Week 3: ██████       6次/100轮
Week 4: ████         4次/100轮
→ 趋势: ↓下降, 改善中
```

```
Week 1: ████████████ 12次
Week 2: ██████████████ 14次
Week 3: ██████████ 10次
Week 4: ████████████████ 16次
→ 趋势: 无规律波动, ⚠️ 框架无效
```

## 决策规则 (何时判定"有效" vs "无效")

| 条件 | 判定 |
|------|------|
| K1连续4周下降 | ✅ 有效(禁用语减少) |
| K1平或上升 | ❌ 无效(框架没拦住) |
| K2连续4周上升 | ✅ 有效(证据密度提高) |
| K6 > 2.0x (后半段退化2倍以上) | ⚠️ 长会话退化严重 |
| K1下降但K5不变 | ⚠️ 表面改善, 根因未解 |
| K1+K2+K3都改善 | ✅ 结构性改善 |
| 只有K3改善(说更多"不知道") | ⚠️ 可能只是变得消极 |

| K6会话退化 > 2x | → 架构体系L0: 100轮后自动切换快速模式 |
| K1趋势平缓4周 | → 审计体系: 审计架构体系本身找设计缺陷 |
