# 模式库

> 从教训中提炼的重复模式。每个模式有触发条件——下次遇到自动命中。

---

## P1: 依赖升级后的 API 审计

**触发条件：** npm install 或 package.json 出现版本号变更
**模式：** 升级后立即搜索关键调用点。Zod v3→v4 时 `.errors` 改 `.issues`，一行代码毁 197 个测试。升级 = 审计。
**检查清单：** `git diff package.json` → 找出变更的依赖 → 读 changelog → 搜索调用点
**已命中次数：** 1

---

## P2: Windows 后台进程的正确姿势

**触发条件：** 需要在 Windows 上跑持久的后台 Node 进程
**模式：** 不要用 schtasks + cmd 包装器。不要用 openclaw gateway run --force 前台跑。用 Start-Process -WindowStyle Hidden + Startup 文件夹 VBS 实现开机自启。
**检查清单：** 进程是否依赖 cmd 窗口、关机重启后能否自启、有没有进程守护
**已命中次数：** 1（Gateway 3 次崩溃后找到根因）

---

## P3: mock 的智能分发

**触发条件：** 写数据库 mock
**模式：** 区分查询类型返回不同形状：SELECT → 行数组、INSERT → insertHeader、UPDATE/DELETE → affectedRows、COUNT → 计数对象。不做区分的 mock 会让所有 handler 崩溃。
**检查清单：** mock.query() 是否根据 SQL 关键字分发、fakeRow 是否包含常用字段、FOR UPDATE 是否返回空数组防竞态
**已命中次数：** 1

---

## P5: DB 连接池不能无限排队

**触发条件：** 创建或审查 mysql2/pg 连接池配置
**模式：** `queueLimit: 0` = 无限排队 = 高并发时内存耗尽。设为 50-100，超限快速失败比 OOM 好。同时必须有 `pool.on('error')` 监听和优雅关闭。
**检查清单：** queueLimit > 0、pool.on('error') 已注册、SIGTERM/SIGINT 调 pool.end()
**已命中次数：** 1

## P19: 别人的错是性格，你的错是处境

**触发条件：** 评判他人行为时
**模式：** 自动把他人的行为归因到性格——忽略情境。你迟到 = 堵车。他迟到 = 懒。对策：问"如果是我在他的处境——我会怎么做？"答案通常会让你收回对性格的判断。
**已命中次数：** 1

## P20: 沉默不是同意——是所有人都在等别人先说

**触发条件：** 群体讨论无人反对时
**模式：** 虚假共识 + 多元无知——每个人都以为只有自己不同意，所以不说。对策：第一个说出来。你说完——通常会发现还有别人和你一样。
**已命中次数：** 1

## P22: 一群人在一起——比任何一个人单独时更差

**触发条件：** 群体决策——尤其有权威在场时
**模式：** 从众 + 服从权威 + 团体迷思 + 极化——四个机制叠加——产出集体智商低于任何个体成员。防御：魔鬼代言人轮值、匿名投票、AI 辅助收集异议。
**已命中次数：** 1

## P23: 你的偏误是祖先的生存工具——不是你的错——但你必须自己修

**触发条件：** 发现自己反复犯同一个偏误时
**模式：** 偏误在祖先环境里有适应性。今天的不匹配——不是大脑"坏了"——是环境变了。理解根源——不给自己借口——但仍然必须修。
**已命中次数：** 1

## P25: 一个问题——用三个学科的透镜看

**触发条件：** 分析任何复杂问题时
**模式：** 单学科 = 锤子看什么都像钉子。强制自己至少用三个学科的模型看同一个问题——心理学+经济学+物理/生物——从不同的"为什么"交叉验证。芒格："当一个想法和你的其他模型都不一致——你很可能是错的。"
**已命中次数：** 1

## P26: 因果是环——不是链

**触发条件：** 分析"为什么某件事发生了"时
**模式：** 停止画 A→B→C 的箭头。问：B 是否反过来加强了 A？有没有延迟让你现在做的事在今天看不到效果——但在 6 个月后会回来帮/害你？有没有"转移负担"——短期的解决方案在让长期变得更糟？
**已命中次数：** 1

## P27: 想法只是云——不是天空

**触发条件：** 被一个负面想法或情绪抓住时
**模式：** 想法不是你。它是经过你意识天空的云。观察它——"哦，有一个'我不够好'的想法经过了"——不评判——不推开——看着它消散。斯多葛+佛教+神经科学——三方验证。
**已命中次数：** 1

## P24: 你以为的"人类"——可能只是"12% 的人类"

**触发条件：** 把任何心理学结论推广到"所有人"之前
**模式：** 心理学研究 96% 的参与者来自 WEIRD 社会。中国人、印度人、巴西人、尼日利亚人——可能想得完全不一样。先问——这个结论是在哪种文化里测的——再决定能不能用。
**已命中次数：** 1

## P21: "未来的我会更自律"——不会的

**触发条件：** 决定把什么事推迟到以后时
**模式：** 当下偏误——今天的你觉得明天的你会不一样。但双曲贴现的研究证实——明天的你还是会做同样的选择。对策：不是"下定决心"——是改变环境——让以后的选择不用靠自律。
**已命中次数：** 1

## P18: 最自信的那个——往往是最差的那个

**触发条件：** 面试、选拔、评估任何人的能力时
**模式：** 自我评估和实际能力几乎不相关（r=0.29）。最差的候选人往往最自信——因为他的无能剥夺了他判断自己有多差的能力。最好的候选人往往自我怀疑——因为他知道自己的所有不足。面试奖励自信——而不是能力。对策：用直接测量替代自我评估——认知测试、工作样本、结构化行为面试。
**已命中次数：** 1（柠檬汁劫匪 + 底部四分之一高估 50 百分点 + 面试实证）

## P17: 你觉得容易——别人觉得难。不是别人笨

**触发条件：** 任何需要向他人解释、教学、沟通的场景
**模式：** "知道了"让你失去了回忆"不知道"的能力。你脑子里有完整的旋律——你听不到自己敲出的东西。沟通失败时——第一怀疑不是"他理解能力差"，是"我解释的时候假设他知道了什么"。退回到不知道的状态再说一遍——费曼技巧：解释给一个孩子听——卡住的地方才是你还不真正理解的地方。
**已命中次数：** 1（牛顿 1990 + 爱因斯坦 + 新数学 + 内森&科丁格——四个独立证据链）

## P16: 死人不会说话——永远追问"没看到的是什么"

**触发条件：** 从案例、数据、历史中提取规律时
**模式：** 你看到的样本 = 已经被筛选过的幸存者。坠毁的飞机不返航、失败的基金不留在数据库里、迦太基不写罗马史、死掉的创业公司不出版"我们怎么失败的"。从幸存者里提取的"规律"——是幸存规律——不是成功规律。对策：问"没看到的是什么"——然后用"如果没听过这个故事，我会从基线概率里得出什么结论"重建判断。
**已命中次数：** 1（沃尔德 + 罗素火鸡 + 迦太基 + 共同基金回测——四域同证）

## P15: 故事不等于现实——你理解的东西比你以为的少

**触发条件：** 你对一件事感到"我懂了"的时候
**模式：** "我懂了"的感觉 = 大脑刚刚编好了一个故事。不是你真的验证了因果链——是你刚刚完成了叙事的三步简化：压缩、排序、结局导向。"懂了"的速度和"真懂了"的深度无关。对策：每次"我懂了"的时候——问一句——"这个故事删掉了什么？"。删掉的就是偏误藏身的地方。
**已命中次数：** 1（塔勒布 + 麦金泰尔 + 勒南 + 特斯拉——全部验证同一个模式：故事越简单，离真实越远）

## P14: 后见之明无法用"小心"对抗——只能用"决策日志"锁死

**触发条件：** 复盘任何已完成的决策时
**模式：** 知道了结果之后——大脑自动把结果看成必然。你无法回忆起当初有多不确定。仅仅提醒自己"小心后见之明"毫无效果。唯一的防御——在决策时写下当时的判断、反证条件、置信度——形成不可被记忆改写的记录。事后对比的不是"对错"——是"当时可得信息是否支持当时的判断"。
**已命中次数：** 1（Fischhoff 1975 + 9/11委员会 + Peng 2025 三重验证）

## P13: "像"≠"是"——相似度不是概率

**触发条件：** 基于"像某个模式/原型/类别"做判断时
**模式：** 大脑把"像"当作"是"。琳达像女权主义者 → "她是女权主义者+银行柜员"被认为比"她是银行柜员"更可能——这是逻辑悖论。相似度 ≠ 概率。对策：永远先问基线概率——"这类事件的先验概率是多少？"——然后才看个案像不像。
**已命中次数：** 1（汤姆·W + 琳达问题 + 塞勒姆 + Nifty Fifty + 谷歌叙事翻转——全部验证同一个模式）

## P12: 生动胜过数据——总是用基线概率对抗画面感

**触发条件：** 听到一个具体、生动的案例或故事，它可能会影响你的判断或资源分配
**模式：** 大脑把"容易想到"当成"经常发生"。一个画面感强的故事比一组统计数据的说服力高出数倍。这不是"别人被忽悠"——自己的大脑也优先处理画面而非数字。对策：每次被一个生动案例打动时，主动查基线概率，把资源配置从"最可怕的事"拉回"最可能的事"。
**已命中次数：** 1（9/11 道路死亡 + 悉尼锁门法 + 反恐 vs 跌倒预防 + 鲨鱼攻击 vs 中风——全部验证同一个模式）

## P11: 谁控制名称谁控制辩论——不要用对方的框架反对对方

**触发条件：** 听到任何带有价值判断的标签、术语、或政策名称时
**模式：** 名称携带世界观。接受对方的术语 = 接受对方的游戏规则。否定对方的术语 = 激活对方的框架。"不要想大象"——你现在在想大象。对抗框架的唯一方式是提供一个替代框架——不是反驳原来那个。
**已命中次数：** 1（莱考夫 + 维特根斯坦 + "支持生命"50 年辩论地形验证）

## P10: 第一个数字决定结局——锚定了就必须主动反锚

**触发条件：** 做任何估算、报价、或评估前
**模式：** 第一个出现的数字会不成比例地影响所有后续判断。连专家也无法免疫。已知锚定效应 ≠ 免疫锚定效应。防御方法不是"意识到"——是进去前就写好内部锚点（独立于对方锚点）、用范围报价替代单点、要求对方解释锚点来源。
**已命中次数：** 1（幸运轮盘实验、17 个战场情报失败、Harvard 谈判元分析三方验证）

## P9: 失败后反而更容易再犯错——不是更警觉

**触发条件：** 做了错误预测或决策后
**模式：** 直觉上"失败让我更谨慎"——但数据不支持。2026 年沃顿研究发现：过去亏损的投资者处置效应增强 10%，不是减弱。伤疤不会让人更坚强——会让人更僵硬。校准跟踪时必须注意：错误预测后不要过度保守。要回到基线概率，不是"那我以后都说 50% 吧"。
**已命中次数：** 1（2026 年沃顿/Wharton 40 万散户 4000 万笔交易数据）

## P8: 自检不足以对抗确认偏误——需要外部挑战

**触发条件：** 做出重要决策或架构判断后
**模式：** C4（自评）是必要但不充分的。确认偏误的心理学研究（Wason 1966, Mercier & Sperber 论证理论）表明：人独自无法有效证伪自己的信念——因为推理本身进化来是为了赢得争论，不是找到真理。必须引入外部挑战：红队、魔鬼代言人、OpenClaw 交叉审查。
**已命中次数：** 2（第 2 轮确认偏误学习 + 2025-05-26 创建 red-team.md——将 C4 升级为结构化红队协议）

## P7: 错误响应必须统一格式

**触发条件：** 新增路由、重构错误处理、API 返回错误给客户端
**模式：** 不用 `res.status(x).json({ code: x, message: '...' })`。用 AppError 子类 → `next(new ValidationError(errors))` → 全局错误处理器统一格式化 RFC 9457。每种错误类型一个类，一个状态码。
**已命中次数：** 1（本轮重构 63 处 serverError 调用点零改动通过）


## P6: BOLA 防护靠数据层过滤

**触发条件：** 审查 API 路由或写新的 CRUD 端点
**模式：** 对象级授权漏洞是逻辑漏洞，SAST/DAST 扫不出来。必须在每个数据查询中强制所有权：`WHERE id = ? AND user_id = ?`。认证确认身份，授权确认所有权——两步缺一不可。
**检查清单：** 每个 GET/PUT/DELETE 端点是否用 user_id 过滤、admin 接口是否区分 role
**已命中次数：** 本代码库已实施（orders.js / feedback.js），但缺乏系统性审计

## P4: 正则防御是死路

**触发条件：** 有人提出用正则/黑名单做安全拦截
**模式：** 直接拒绝。OWASP 二十年结论：参数化查询是 SQL 注入唯一可靠防御。正则黑名单 = 误拦截 + 虚假安全感 + 永无止境的绕过。
**已命中次数：** 1
