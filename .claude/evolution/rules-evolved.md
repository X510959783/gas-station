# 进化规则

> 足够稳定的模式变成规则。每次会话自动加载，成为肌肉记忆。

---

## R1: 改动前先审计

**规则：** 任何涉及"修改安全策略"或"删除/添加中间件"的提案，必须先跑全仓审计拿到数据，再给建议。不许先判再审。
**来源：** P4 + 2026-05-25 安全中间件反转
**适用：** 安全、中间件、架构决策

## R2: 依赖升级必须审查调用点

**规则：** npm install 变更了任何依赖版本后，立即搜索该依赖的所有调用点，确认 API 兼容。不假设"小版本升级没事"。
**来源：** P1 + Zod v3→v4 事故
**适用：** 所有 npm 操作

## R3: Windows 后台服务不用 schtasks

**规则：** 在 Windows 上部署长期运行的 Node 后台服务，直接用 Start-Process -WindowStyle Hidden + 开机自启脚本。不经过 Task Scheduler。
**来源：** P2 + Gateway 3 次崩溃
**适用：** Windows 运维

## R4: DB 连接池必须设上限

**规则：** mysql2/pg 连接池 queueLimit 必须 > 0。pool.on('error') 必须注册。应用关闭时必须 pool.end()。
**来源：** P5 + 外部研究确认
**适用：** 所有数据库初始化代码

## R5: API 端点必须有所有权校验

**规则：** 任何返回/修改用户私有数据的端点，SQL 查询必须包含 `AND user_id = ?`。admin 接口除外但必须有 role 检查。
**来源：** P6 + OWASP API1:2023 (BOLA)
**适用：** 所有 CRUD 路由
