# 深挖方法论 v3.1 — 闭环修复引擎(研究验证版)
# 升级: 2026-05-28 | 基于 EviBound双门 + Judge Agent驳回 + NYU交叉验证 + 9轮审计非单调性
# 替代: v3.0的单门验证管道

## v3.0 → v3.1 升级点

```
v3.0: 发现→分类→修复→验证→关闭        (单门, 自验证, 假设单调)
v3.1: 发现→分类→修复→预审批→验证→(驳回→重修复→预审批→验证)→关闭|不可解
                         ↑_____________↑
                         最多3轮驳回循环
```

## 5项升级

### 升级1: 双门验证 (来自 EviBound, Cornell Nov 2025)
- 门1(预审批): 修复方案合理吗？是否解决了根因而非症状？修复是否会引入新问题？
- 门2(验证): 修复声称的效果是否实际产生？(git diff/命令输出/文件对比)
- 双门都通过→进入CLOSED。任一不通过→进入驳回循环。
- 研究支撑: 双门=0%幻觉 vs 单门=25%幻觉 vs 无门=100%幻觉

### 升级2: 驳回-重修复循环 (来自 Judge Agent, Mar 2026)
- 验证失败→驳回(附带失败原因)→重新修复→重新双门验证
- 最多3轮驳回。连续3轮失败→标记为"结构性不可解"而非CLOSED
- 研究支撑: 3轮驳回将静默失败率从42%→1.5%

### 升级3: 交叉验证(模拟跨模型→实际外部) (来自 NYU 37模型研究, Nov 2025)
- 自验证偏差: 模型偏好与自身推理模式相似的解决方案
- 缓解A(即时): 每次验证时显式生成2个"反对论点"(模拟另一个模型的视角)
- 缓解B(定期): 每周至少一次用实际的不同模型验证关键结论(Agent工具, subagent_type不同)
- "如果Gemini审计这个修复, 它会指出什么问题？"≠真正的Gemini审计
- ⚠️ 缓解A是伪交叉验证(#472)——同一模型模拟≠真正外部。缓解B是真正的交叉验证但频率低。
- 研究支撑: 跨家族验证始终优于自验证

### 升级4: 非单调性接受 (来自 9轮审计研究, May 2026)
- 接受修复可能引入新缺陷(缺陷数会振荡)
- 每次修复后额外检查: "这个修复引入了什么新问题？"(升级1的门1已包含)
- 跟踪指标: 新增缺陷数/修复轮次——预期短期内会上升
- 研究支撑: 9轮审计实证缺陷数从15→振荡→0

### 升级5: 不可解分类 (来自 Judge Agent 1.5%残差, Mar 2026)
- CLOSED: 修复已验证, 效果确认
- UNRESOLVABLE: 结构性不可解(如#31 NP完全, #44 递归病理, #2 模型单点故障, #4 不可审计)
- 不可解≠失败——承认边界是成熟系统的标志
- 研究支撑: 1.5%残差集中在数学可认证性崩溃的"分叉点"

## 更新后的操作规则

1. 原子修复: Fix + DualGate(预审批+验证) + Proof (不变)
2. 发现/修复比 ≤ 3:1 (不变)
3. 外部镜像: 每周 + 每次自验证时模拟反对论点 (新增)
4. 结构化追踪: OPEN→ANALYZED→IN_FIX→PRE_APPROVED→VERIFIED→CLOSED|UNRESOLVABLE (新增2个状态)
5. 期望vs现实差异: (不变)
6. 老板=断路器: (不变)
7. 驳回上限: 同一修复最多3轮驳回 (新增)
8. 非单调性监控: 跟踪修复引入的新缺陷 (新增)
