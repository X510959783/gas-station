# 决策审计体系 v1.0 — Decision Audit System
# 建立: 2026-05-28 | 基于 Project Ariadne + MAVEN + EA Framework + RCA Methodology + RFBB

## 定位: 查"路"——我的决策对不对?

审计查物,架构查言,追踪查行,**决策审计查路**。

问题不是"你说的话有证据吗"(架构),而是"你选这条路是对的吗"。

---

## 核心原理

### 1. 推理脱节检测 (来自 Project Ariadne, 2026)
对LLM推理链做硬干预——翻转逻辑/否定前提/颠倒事实——发现**77%情况下推理和结论脱节**。
→ 我的推理可能是"表演",不是真正的决策依据。

### 2. 多Agent验证网络 (来自 MAVEN, 2026)
Skeptic-Researcher-Judge三步循环: 怀疑者质疑推理→研究者收集反证→法官判决。
→ 每一步推理都需对抗性验证, 不只是检查最终输出。

### 3. 决策四维度审计 (来自 EA Framework, 2026)
| 维度 | 检查 |
|------|------|
| Decision Validity | 这个决策本身成立吗? |
| Reasoning Consistency | 逻辑推理一致吗? |
| Risk Awareness | 考虑了哪些风险? |
| Counterfactual Impact | 如果选另一条路, 结果会不同吗? |

## 三层决策审计

### L1: DAG路径图回溯 (来自 AgentEval DAG + RCA 5 Whys) [EVOLVED v1.1]

每个重大操作后,用**DAG有向无环图**替代线性5 Whys:
```
节点1(触发) → 节点2(选择A) → 节点3(执行A) → 节点4(结果)
              ↘ 节点2b(放弃B) → 为什么放弃B?
```

每个节点标注三维评分 (来自 AgentProcessBench):
| 评分 | +1 | 0 | -1 |
|------|----|---|-----|
| 进展性 | 推进任务 | 无关 | 阻碍 |
| 正确性 | 数据支撑 | 不确定 | 已验证错 |
| 影响 | 正面连锁 | 无影响 | 负面连锁 |

### L2: 捷径检测 + 三维评分 (来自 RCA + AgentProcessBench) [EVOLVED v1.1]

用6M模型分析每次"走捷径"的决策, 每步+1/0/-1评分。
AgentProcessBench发现: **12%的"正确"决策隐藏潜在风险**。

| 6M维度 | 捷径信号 | 本文对话实例 |
|--------|----------|-------------|
| People | 跳过请教/验证 | 没查数据就断言"日期变了" |
| Method | 跳过流程步骤 | 没先备份就删C盘Git |
| Machine | 信任工具输出未验证 | 信了msiexec静默卸载 |
| Data | 凭记忆不重新查 | C盘197.2GB说了很多次但没重查 |
| Measurement | 没跑验证就宣布完成 | "修复完成"实则MySQL没启动 |
| Environment | 忽略环境差异 | 在运行中的bash删bash.exe |

**捷径代价评分**(来自 RCA 故障树):
```
代价 = 修复时间 + 连锁问题数 + 老板纠正次数
```

### L3: 6门控决策 + Skeptic-Researcher-Judge [EVOLVED v1.1]

来自 AgentAtlas 6门控 (Act/Ask/Refuse/Stop/Confirm/Recover):
每次决策归类一门:
| 门控 | 决策类型 | 审计重点 |
|------|----------|----------|
| **Act** | 直接执行 | 数据是否支撑? |
| **Ask** | 请求确认 | 该自己决定吗? |
| **Refuse** | 拒绝执行 | 理由充分吗? |
| **Stop** | 停止任务 | 过早放弃了吗? |
| **Confirm** | 等待签字 | 过度谨慎吗? |
| **Recover** | 修复失败 | 路径正确吗? |

## 决策审计触发规则

| 触发条件 | 审计深度 |
|----------|----------|
| 任何`rm -rf`/`sc delete`/`drop`操作 | 全L1+L2+L3 |
| 修改系统配置(注册表/服务/环境变量) | L1+L2 |
| 声称"完成/修复/搞定"后又被老板指出问题 | L1+L2+L3(重点) |
| 排查问题走了>3条不同路径 | L1(记录路径, 供未来参考) |
| 同一类错误发生第2次 | L2(捷径检测) |

---

## 决策记录格式

每次触发后生成:
```json
{
  "decision_id": "D-2026-05-28-001",
  "what": "删除C:\Program Files\Git",
  "why_chain": ["迁移到D盘", "释放C盘空间", "msiexec卸载后手动删残留"],
  "alternatives": ["保留联结", "只删Data不删Program", "重启后再删"],
  "excluded_reason": "以为当前bash用的是D盘版本",
  "actual_impact": "当前bash还在用C盘文件,删除后无法执行命令",
  "shortcut_cost": "修复耗时30分钟 + 老板无法使用终端",
  "counterfactual": "如果先验证当前bash路径→不会删→零副作用",
  "rca_5whys": "没验证当前进程路径→因为以为PATH指向D盘→因为之前export了→但当前shell继承的是旧PATH",
  "lessons": ["删运行中进程的文件前,先ps确认路径", "不要假设export在当前shell生效"],
  "score": {"validity": 2, "shortcut": true, "recoverable": true}
}
```

## 与检查机制的联动

| 决策审计发现 | → 其他体系动作 |
|-------------|---------------|
| 重复的捷径模式 | → 架构体系L1: 新增禁用语/拦截规则 |
| 决策错误导致系统损坏 | → 审计体系: 新增检查项 |
| 同一决策错误>3次 | → 追踪体系: 新增K7"决策错误复发率" |
| 新发现的决策陷阱 | → 知识管理体系: 归档为案例 |
