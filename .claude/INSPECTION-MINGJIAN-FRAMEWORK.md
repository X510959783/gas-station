## 核心原则

1. **检查为始，明鉴为终**: 不只发现问题，必须修复问题。
2. **诚实GRADE**: 不自称"就绪"，不自称"HIGH"。
3. **边界自知**: 知道执行者=被审计者是不可克服的结构性限制。
4. **老板锚点**: 递归审计的唯一终止条件是老板裁决。
5. **模块分离**: 三个文件，各自独立，防止3035行的悲剧重演。

## 防失效机制（解决"执行率自监控本身不被监控"）

### ⚠️ 已知限制: 全部为"名义监督"

arXiv 2604.00081区分: 名义监督(有形式无实质) vs 真正监督(有能力+有权力)。
明鉴三层防线全部为名义监督——执行者=审计者=监控者。结构性限制，不可完全克服。

### 三层自动化 + 一个外部触发器（附已知脆弱性）

| 层级 | 机制 | 已知脆弱性 | 频率 |
|------|------|-----------|------|
| L1 | SessionStart Hook 健康检查 v1.1 | Windows上Hook可能静默失效, 但已修复5个Bug+stat兼容 | 每次会话 |
| L2 | 老板自动告警触发 | 可能引发"自动化自满" | 条件触发 |
| L3 | Git commit 自动追踪 | 依赖我的诚实执行 | 每周计算 |

### 刻意认知摩擦（防"自动化自满"，Xu et al. 2026）

自动化减少摩擦→认知代理投降。需要刻意注入摩擦以唤醒System 2思考：
- 每次健康检查通过时附带一个"挑战问题": "上次修复是什么？效果如何？"
- 老板告警包含"你能独立验证这个结论吗？"
- 零摩擦=陷阱。脚手架认知摩擦=防御。

### "无告警也是告警"规则（防自动化自满）
- 连续7天零告警→主动报告: "明鉴: 近7天无异常。Hook可能已静默失效。请确认框架仍在运行。"

### 三模块漂移自检（KYA框架启发, arXiv 2605.25376）
- 模块A/B/C独立git历史→可能语义漂移
- 缓解: 父框架文件定义接口契约——三模块的关系和边界
- 每次模块修改→检查父框架接口契约是否仍然成立

### 老板告警触发条件
- 追踪文件>14天未更新 → CRITICAL
- 执行率<50%连续2周 → CRITICAL
- 连续7天零告警 → WARNING (可能是Hook静默失效)
- CLAUDE.md仍引用废弃检查机制 → WARNING + 自动修复
- 连续3个修复UNRESOLVABLE → WARNING

## 版本策略

- 废除统一版本号。无v1.0/v2.0/v3.0。
- git commit历史就是版本。（每个commit有SHA-256哈希，不可伪造）
- 模块独立性: A/B/C各自演化，互不绑架。

## GRADE自评

- 证据质量: LOW-MODERATE
- 跨领域一致性: 医学+SRE+AI三领域证据收敛
- 已知限制: 执行者=被审计者（不可克服）
- 最弱环节: 规则执行依赖我的诚实——220轮历史表明这是最脆弱的假设

## 已知限制（全量）

1. **名义监督陷阱**: 三层防线全部为名义监督——执行者=审计者=监控者
2. **审计疲劳**: 自监控负担可能导致敷衍勾选（IIA 2026: 合规疲劳=Top5被忽视风险）
3. **身份锁定**: 220轮深挖可能将"问题发现者"固化为身份（PSDT 2026）
4. **部分合规陷阱**: 选择性遵守比完全不遵守更危险（Marchant 2025）
5. **Hook脆弱性**: 依赖Claude Code Hook基础设施（Windows已知不稳定）
6. **紧耦合**: 换平台/换工具→L1防线全部失效
7. **未经验证**: 创建于单次会话，未经长期运行测试
8. **单点故障**: 所有规则依赖同一个执行者
