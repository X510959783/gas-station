## 防失效机制（解决"执行率自监控本身不被监控"）

### ⚠️ 已知限制: 全部为"名义监督"

arXiv 2604.00081区分: 名义监督(有形式无实质) vs 真正监督(有能力+有权力)。
明鉴三层防线全部为名义监督——执行者=审计者=监控者。结构性限制，不可完全克服。

### 三层自动化 + 一个外部触发器（附已知脆弱性）

| 层级 | 机制 | 已知脆弱性 | 频率 |
|------|------|-----------|------|
| L1 | SessionStart Hook 健康检查 v1.1 | Windows上Hook可能静默失效, 但已修复5个Bug+stat兼容 | 每次会话 |
| L2 | 老板自动告警触发 | 可能引发"自动化自满" | 条件触发 |
| L3 | Git commit 自动追踪 | 依赖我的诚实执行 | 每周计算 |

### 刻意认知摩擦（防"自动化自满"，Xu et al. 2026）

自动化减少摩擦→认知代理投降。需要刻意注入摩擦以唤醒System 2思考：
- 每次健康检查通过时附带一个"挑战问题": "上次修复是什么？效果如何？"
- 老板告警包含"你能独立验证这个结论吗？"
- 零摩擦=陷阱。脚手架认知摩擦=防御。

### "无告警也是告警"规则（防自动化自满）
- 连续7天零告警→主动报告: "明鉴: 近7天无异常。Hook可能已静默失效。请确认框架仍在运行。"

### 三模块漂移自检（KYA框架启发, arXiv 2605.25376）
- 模块A/B/C独立git历史→可能语义漂移
- 缓解: 父框架文件定义接口契约——三模块的关系和边界
- 每次模块修改→检查父框架接口契约是否仍然成立

### 老板告警触发条件
- 追踪文件>14天未更新 → CRITICAL
- 执行率<50%连续2周 → CRITICAL
- 连续7天零告警 → WARNING (可能是Hook静默失效)
- CLAUDE.md仍引用废弃检查机制 → WARNING + 自动修复
- 连续3个修复UNRESOLVABLE → WARNING

## SGM闸门+三层增强：从统计保证到确定性可审计

### SGM基础（Statistical Gödel Machine, arXiv:2510.10232）
**累积安全保证: Pr(任何轮次接受有害修改) ≤ δ = 0.01**

### 三层增强（超越纯统计→确定性+持续+多角色）

**增强L1: QONC透明度证明（Zenodo 2026）——每次修复可被独立重放审计**
- git commit附带"零副作用声明"+SHA-256验证证据
- 任何第三方可独立验证修改的正确性——不需要信任执行者
- 透明度日志=不可伪造的审计链

**增强L2: 运行时持续验证（FlyCatcher 2026 + ReasonOps）——修复后持续漂移检测**
- SGM闸门=修复前。运行时验证=修复后持续监控。
- 每次会话自动运行健康检查→检测框架是否静默退化

**增强L3: 多角色审查（Wix Gandalf 2026）——Detector≠Coder≠Reviewer**
- 显式角色切换: 发现/修复/审查模式——间隔≥1轮
- Gandalf实证: 角色分离将Agent间错误从50%→1%

### 修复前5步SGM闸门（替代原有门1+门2）

每次修复EXECUTE之前，强制执行5步：

**S1: 克隆（Sandbox）**
- git worktree创建修复分支——修复在隔离环境中测试
- 主分支不受影响——零风险预览

**S2: 对照实验（旧vs新）**
- 修复前运行明鉴健康检查→记录基线
- 应用修复→运行相同健康检查→记录结果
- 对比: 修复是否改善或至少不退化？

**S3: 副作用穷举（FMEA事前验尸）**
- 穷举所有可能的失败模式（至少3个）
- 每个失败模式: 检测条件+回滚方案
- 如果回滚成本>3步→拒绝修复

**S4: 统计闸门（SGM核心）**
- 提出假设: "此修复改善了框架状态"
- 证伪尝试: 至少2个反对论点(模拟外部审计者)
- 如果反对论点被证实→驳回修复
- 如果反对论点被证伪→通过闸门

**S5: 回滚准备**
- git revert命令已就绪
- 回滚触发条件已定义
- 修复后监控窗口(至少3轮对话)确认无副作用

### 全局错误预算
δ = 0.01: 所有修复中接受有害修改的概率≤1%
每次修复消耗δ_t = δ / (t+1)² (谐波分配——后期更严格)
错误预算用尽→停止修复→请求老板裁决
