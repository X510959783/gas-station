## 核心原则

1. **检查为始，明鉴为终**: 不只发现问题，必须修复问题。
2. **诚实GRADE**: 不自称"就绪"，不自称"HIGH"。
3. **边界自知**: 知道执行者=被审计者是不可克服的结构性限制。
4. **老板锚点**: 递归审计的唯一终止条件是老板裁决。
5. **模块分离**: 三个文件，各自独立，防止3035行的悲剧重演。

## 防失效机制（解决"执行率自监控本身不被监控"）

### 三层自动化 + 一个外部触发器

| 层级 | 机制 | 解决什么 | 频率 |
|------|------|---------|------|
| L1 | SessionStart Hook 自动健康检查 | 框架被遗忘——每次会话提醒 | 每次会话 |
| L2 | 老板自动告警触发 | 外部锚点从未激活——自动上报 | 条件触发 |
| L3 | Git commit 自动追踪执行率 | 手动追踪负担——自动化 | 每周计算 |

### 老板告警触发条件（自动，不等待老板问）
- 追踪文件>14天未更新 → CRITICAL → 请求裁决框架存废
- 执行率<50%连续2周 → CRITICAL → 报告框架可能已失效
- CLAUDE.md仍引用废弃检查机制 → WARNING → 自动修复+报告
- 连续3个修复UNRESOLVABLE → WARNING → 请求老板介入

## 版本策略

- 废除统一版本号。无v1.0/v2.0/v3.0。
- git commit历史就是版本。（每个commit有SHA-256哈希，不可伪造）
- 模块独立性: A/B/C各自演化，互不绑架。

## GRADE自评

- 证据质量: LOW-MODERATE
- 跨领域一致性: 医学+SRE+AI三领域证据收敛
- 已知限制: 执行者=被审计者（不可克服）
- 最弱环节: 规则执行依赖我的诚实——220轮历史表明这是最脆弱的假设
